Arrmes is useful, but the broad claim remains unqualified

The published specialist beats the tested untuned baselines on these media-routing tasks. Its fresh diagnostic score is 63/80 raw exact and 68/80 after the verifier, below the historical sealed-suite headline. A CPU GGUF path retains similar aggregate quality while changing individual predictions.

This report separates model predictions, format translation, policy correction and real fixture execution. A verifier rejection or correction never counts as a correct raw model prediction. These authored diagnostic tasks are not a comprehensive product acceptance test.

Where the baselines fail

Qwen3 1.7B often emits correct-shaped bare JSON rather than the required native wrapper: strict native accuracy is therefore lower than translated semantic accuracy. Both numbers are shown. Granite community Q4 emits prose refusals even on its publisher's simple weather-call example, while publisher BF16 passes that smoke test; its quantization and native argument-string compatibility require care. These are measured configurations, not a claim that every Granite or larger-model setup has this quality. The stronger Qwen3 4B Instruct reference is a genuine tool-capable general model, not a fabricated competitor. No prompt tuning was done to improve these held-out comparisons after results.

Comparable existing approaches

A real pyarr 6.9.0 client made 30 structured read operations on the same Sonarr/Radarr fixtures: 20 matched the exact per-entity checks, with zero mutations. TV and movie lookup succeeded; the per-series missing helper exposed the fixture/API filter mismatch because the returned wanted list contained other series. This is caller/API semantics, not an NLP quality score. Median client operation time was 1.56 ms without any language model.

pyarr provides broad typed service clients and leaves natural-language intent, caller identity and confirmation policy to its host application. MediaStack MCP documents observation and two-step-confirmed actions across media services, including subtitle search and requests. It uses an external model/controller and a different service/retention architecture; its documented coverage is a useful product reference. Its live code and safety were not executed in this comparison, so no numerical quality or performance ranking is assigned.

Reproduce

Use an isolated environment and locally pinned model artifacts. The core package has no model-runtime requirement. Select optional MLX on Apple Silicon or a native GGUF runtime on PATH. Charts need matplotlib and numpy. Run one model process at a time; all evaluation traffic stays on allowlisted loopback fixture/inference ports.

What remains uncertain

  • Broad new service coverage is evaluated separately from the released model contract; adding adapter operations does not prove the released model can select them.
  • Native Windows CPU and Windows CUDA generation remain hardware-untested. Linux x86 CPU/CUDA and Mac MLX/ARM64 CPU are actually measured here. Other accelerators, concurrent load, real service-version diversity and full production workflows remain unqualified.
  • A truly scenario/entity/template-disjoint acceptance cohort must be authored and frozen after these diagnostics, without training on or selecting prompts against it.
  • Long compound workflows, long conversations, external networks, service response drift and confirmation delays remain outside this compact benchmark.
  • Published model provenance and legacy performance/accuracy claims need correction and review before calling Arrmes a comprehensive portable tool.
